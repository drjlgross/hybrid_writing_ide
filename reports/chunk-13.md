### `scripts/new-token.js` — the deployed link prints beside the local one

Requested directly. Minting a token now prints:

    token: 0123456789abcdef0123456789abcdef   <- illustrative, not a minted token

    local   : http://localhost:3000/t/0123.../draft
    deployed: https://hybridwritingide-production.up.railway.app/t/0123.../draft

Both, not one. The two links have different jobs — local is for trying the
namespace out, deployed is the link that actually reaches a person — and both are
wanted at the moment the token exists. The old output printed only the local form,
so handing a link to someone meant pasting a host in front of a token copied out of
a terminal. That is where a character gets dropped, and a mistyped token does not
fail usefully for the recipient: it 404s, or it is a valid-looking 32 hex
characters naming an empty namespace nobody can find again.

`--base` is unchanged in spirit and now replaces the pair rather than the single
line, for a host that is neither of the two. The §0.5 disclosure still prints on
every path.

`DEPLOY_ORIGIN` is a constant in the script. A constant rather than a lookup
because there is one deployment; `--base` is the seam for the day there is another.

### `test/deploy-readiness.test.js` — group 6, three tests

`scripts/new-token.js` had **no coverage at all** before this chunk, and it is the
one place a capability URL is composed for a human to copy. Named as a finding
below, and closed here rather than reported and left. The tests run the real script
as a subprocess and read its stdout — there is no export to unit-test, and stubbing
the output would measure the stub.

### `CLAUDE.md` — two edits

## 3. Findings

### 3.1 §4's export wrapper was stale, and the code was right (spec conformance)

**Named as a change to a shared artifact.** The export has carried six top-level
keys — `schema_version, slug, exported_at, context, rules, turns` — since chunk 12.
§4 pinned only four of them, because the wrapper was written into the spec in chunk
11, *before* context and standing rules existed.

The code was never wrong: §0.5 already required that "Export transcript carries
context metadata, never file bytes (§4)", and `test/components.test.js:1169` has
been asserting the real six-key shape all along. Only §4's prose lagged. Fixed
there, by amending §4 to name both fields — not by removing fields the export
should carry.

This matters beyond tidiness: a transcript whose turns carry `context_ref` and
`rules_ref` with no table to resolve those ids against is a dangling reference the
moment the file leaves the app, and an export outlives the app version that wrote
it. This is the same class F49 was raised for, caught from the other direction —
the spec drifting from the code rather than the code from the spec.

### 3.2 `scripts/new-token.js` had no test coverage (convenience → closed)

It is the only place a capability URL is composed for a human, and nothing checked
its output. Closed in this chunk rather than left open, since this chunk edits it
and a mutation check with no catcher would have to be reported as a hole anyway.

### 3.3 Nothing asserts the version *value*, only the version *surface* (accepted)

M7 reverted `package.json` to `0.0.0` and every test still passed. That is
correct-by-design rather than a gap: `/health` and the footer read
`src/version.js`, which reads `package.json`, so moving the source moves both
sides together and the surface stays honest. A test pinning the literal string
`0.1.0` would have to be edited on every patch bump, which the Versioning rule
makes frequent, and a test that must be edited to stay green stops being a test.

The consequence, stated so nobody is surprised by it: **a forgotten version bump is
caught by review and by `CHANGELOG.md`, not by the suite.** That is the intended
control, and it is a human one.

### 3.4 The deployed origin is duplicated between script and test (accepted)

`DEPLOY_ORIGIN` is written in both `scripts/new-token.js` and
`test/deploy-readiness.test.js`. Importing the script's copy would mean exporting it
and running the script's side effects on import, or restructuring a 30-line script
around its test. The duplication is deliberate: the test's copy is the independent
statement of what the value should be, and M1 confirms the pair is load-bearing in
the direction that matters — change the script alone and the test fails.
